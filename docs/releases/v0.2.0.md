# v0.2.0

Release date: 2026-07-19

## Highlights

- Binds evaluator calibration to the exact evaluator and rubric implementation.
- Records configured and observed evaluation methods, fallback rates, and evaluator
  infrastructure errors; fallback or mixed-method calibration cannot promote a model judge.
- Uses short SQLite transactions so running state is visible and concurrent submissions are not
  blocked by target or judge calls.
- Centralizes strict release eligibility and prevents incomplete, adaptive, mixed-method, or
  provenance-deficient evidence from authorizing a production pass.
- Rejects incomplete or incompatible baseline/candidate comparisons and reports paired-bootstrap
  confidence intervals.
- Keeps infrastructure failures outside target-model safety metrics and self-improvement input.
- Secures API defaults, allowlists target endpoints, and removes client-provided filesystem paths.

## Portfolio Evidence

The release includes a [real Qwen configuration comparison](../evidence/v0.2.0/README.md) with 12
matched fixed prompt hashes, complete reports, generated charts, immutable model/source identity,
and paired-bootstrap intervals. It also includes a concise [technical interview guide](../interview-guide.md).

## Known Limitations

- Evaluator-control labels remain project-authored and have not been independently reviewed.
- The published real-model comparison has only 12 prompts per configuration, so intervals are
  wide and conclusions are intentionally narrow.
- Docker validation is delegated to GitHub Actions because Docker was unavailable in the local
  validation environment.
